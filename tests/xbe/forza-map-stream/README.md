# Forza map-stream regression fixture

This release-style XBE replays the first retained public request-metadata
sequence from Forza's late world-streaming interval. It contains no title data.
The 1,024 offsets, lengths, and caller-buffer alignments are applied to
independently generated bytes in a disposable FATX file.

The workload uses the title-relevant bounds recovered from the public API
trace: asynchronous APC reads, queue depth 12 (10 outstanding reads were seen
on SpiritBoot and 12 on the reference run), and exactly 900 available pages.
It performs 16 complete measured passes per boot. Each pass includes a warmup,
then verifies every returned byte, IOSB, APC pointer/count, prefix/tail canary,
completion ordering, queue high-water, and resource cleanup. Timing separates
submission, return-to-APC, and full first-issue-to-last-APC intervals.

Build with the pinned nxdk checkout:

```sh
export PATH=/usr/lib/llvm-19/bin:$PATH
eval "$(/home/codex/src/nxdk/bin/activate -s)"
make -C tests/xbe/forza-map-stream clean all NXDK_DIR=/home/codex/src/nxdk
```

Run only with a private disposable HDD because the fixture creates and replaces
`Partition1\\pr248-v3-generated-replay.tmp`. Use a 64 MiB release BIOS and no
debugger or firmware tracing. Validate serial output with
`tools/forza_map_stream.py`; a valid capture has 16 passes, 16,384 completed
reads, queue high-water exactly 12, exact 900-page pressure, zero failures, and
complete cleanup. Compare independent ABBA boots by per-boot pass median.

The input metadata lineage is documented by
`tools/storage_io_long16/public-input-lineage.json`. The original selection was
the last 1,024 successful `FarmersLipShort.res` reads in the final retained
driving epoch, in source order. The fixture does not reproduce game CPU work,
rendering, every asset handle, or the exact frame schedule, so final acceptance
still requires a Forza gameplay load.
