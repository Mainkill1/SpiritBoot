# Generated submission-burst experiment

This standalone release XBE tests whether native submission cost can consume a
small per-frame issue budget before a generated data/512-byte pair is fully
issued. The budgets are a synthetic hypothesis, **not known title constants**.
It complements the frozen `forza-callback-cadence` fixture without changing it.
There is no firmware change or title code/data in this fixture.

## Launch and expected output

Boot `forza-submit-bursts.iso` on a private writable HDD with formatted
Partition1 (E:) and at least 8 MiB free. Capture COM1 at 115200 8N1; there is no
graphical display. Allow at least 180 seconds, or 240 seconds for a slow host.
The eight measured cases each run for at least ten guest performance-counter
seconds; file setup, full oracles and serial output add host time. The program
requests poweroff after its final marker.

No preparation or selector is required. The fixture creates/overwrites only
`E:\forza-submit-bursts-generated.tmp`, fills all 8 MiB with a deterministic
absolute-offset pattern, flushes and closes its synchronous writer, then opens
an asynchronous `FILE_NO_INTERMEDIATE_BUFFERING` reader. It leaves the private
generated file for reruns. It never opens a raw disk device.

A complete success contains seven `FORZA-BURST-MM` observations, eight matching
`CASE`/`TIMING` records, two `SIZE` records per case, the required `OP`/`FRAME`
samples, ten TAP passes, and `FORZA-BURST-END failures=0`. Early exit, absent
records, timeout or a nonzero failure count is not qualification.

## Statistics-query prelude

Before the streaming setup, a public `MM_STATISTICS` structure and four ULONG
canaries on each side are initialized entirely to `0xa5`. Each call replaces
only `Length` with one of:

`0`, `1`, `35`, `36`, `37`, `0xc1008c48`, `0xffffffff`.

Each `MM` row prints input length, return status, all nine resulting fields,
and all eight canaries. Fields are `length`, `total`, `available`, `committed`,
`reserved`, `cache`, `pool`, `stack`, and `image`, corresponding in order to the
public structure. All values except row index are hexadecimal. The prelude
asserts surrounding canary integrity. Statuses and field writes on invalid
lengths are observations; unsuccessful calls are allowed to change fields.
Neither this prelude nor its analyzer assumes a specific failure status.

## Burst policy and case matrix

Eight request slots retain separate IOSBs, buffers, callback records and
canaries. Each pair consists of a generated 65,536-byte request followed by a
512-byte request at the next file offset. Pair bases vary deterministically
within the private file. This is an owned synthetic sequence, not a replay of
actual title request metadata.

At each frame boundary, completed requests are checked byte-for-byte and
retired after a further alertable poll. Eligible slots are prepared before the
burst clock begins. A burst issues at most one request per eligible slot, up to
eight requests. `NtReadFile` receives exported `NtUserIoApcDispatcher` and a
Win32-style completion routine. Every accepted submission is immediately
followed by `KeDelayExecutionThread(UserMode, TRUE, zero)`.

The first request proceeds even if its submission exceeds the budget. After
each call and its immediate poll, the fixture checks cumulative burst time; an
exhausted budget prevents further issues in that burst. The budget includes
alertable polls and bookkeeping as well as the native read calls. Completed slots are
not prepared/reused inside a burst. The next 33 ms interval is a blocking
non-alertable delay, followed by an alertable poll. The same cycle repeats for
at least ten seconds, then all outstanding callbacks are drained and verified.

| IDs | Target free pages | Burst budgets, in ID order |
| --- | ---: | --- |
| 0–3 | 783 | 250 µs, 500 µs, 1,000 µs, uncapped |
| 4–7 | 900 | 250 µs, 500 µs, 1,000 µs, uncapped |

Uncapped still means at most eight submissions, one per slot eligible at burst
entry. Pressure is established after permanent buffers/file handles exist;
entry pages must equal the target. Final pages are reported. Pressure is not
silently rebalanced during measurement.

Completion checks cover IOSB identity, issuer identity, exactly-once count,
Win32 error, status/count publication, allowed alertable phase and non-reentry.
No IOSB poll substitutes for a callback. Full generated bytes, prefix/tail
canaries and IOSB guards must pass before slot reuse. Timeout paths retain
caller storage/handles until poweroff. Normal completion drains callbacks
before closing the file and freeing the slab.

## Measurements and analysis

```sh
python3 tests/xbe/forza-submit-bursts/analyze.py serial.log > summary.json
python3 -m unittest discover -s tests/xbe/forza-submit-bursts -p test_analyze.py
```

The analyzer requires a complete eight-case matrix, all seven statistics
observations, both size summaries per case, the first 64 request samples and
first 32 frame samples (or all when fewer exist). It checks count/byte totals,
sample ordering, slot lifetime, depth limits, pair accounting, canaries and
strict minimum duration using **that run's** reported counter frequency.

- `CASE`: submitted/verified/callback counts, verified bytes, elapsed ticks,
  frame count and peak callbacks outstanding.
- `SIZE`: separate native submit-return and submit-callback sums/maxima for
  65,536-byte and 512-byte requests.
- `TIMING`: budget crossings, empty immediate polls, pair issue gaps, pairs
  issued in the same/different frames, cumulative burst and poll costs.
- `OP`: first 64 request lifetimes, including slot, sequence, byte count,
  offset, frame and burst-entry timestamp.
- `FRAME`: first 32 burst spans, outstanding counts, issue count,
  budget-hit flag, native-submit sum and alertable-poll sum.

A budget-hit flag records a crossing even if that request also consumed the
last eligible slot; it does not by itself establish that budget limited work.
Compare issue counts and pair-frame placement together with cost measurements.

Payload preparation and validation are outside each submission burst but
inside case elapsed time, so throughput includes fixture oracle overhead.
The 33 ms interval blocks the issuer; it does not reproduce runnable frame
rendering/decompression. The eligible slot set is fixed at burst entry. Native
storage completion is not timestamped. The fixture measures public submission
and callback behavior; it does not establish the title's scheduler or allocator
policy. No comparative performance claim follows from compilation alone.

## Build

```sh
export NXDK_DIR=/home/codex/src/nxdk
export PATH="$NXDK_DIR/bin:/usr/lib/llvm-19/bin:$PATH"
make -C tests/xbe/forza-submit-bursts -j4
```

The fixture uses `-O2 -mno-sse -mno-sse2`, with `-Werror` scoped to `main.c`.
It uses the SDK dependencies already rebuilt with those safety flags for the
cadence fixture. Rebuild dependencies with `make -B` if compiler flags change.
SSE generation is disabled to avoid the installed clang 19.1.7 issue documented
by the cadence fixture. The SDK linker's existing section-merge warning remains.
