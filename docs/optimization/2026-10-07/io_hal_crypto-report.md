# I/O, HAL, crypto, debug and image-loading export cost audit

Completed source-guided assessment of **114 assigned exports**: 81 no-change, 10 candidate-backed, 6 stub/default-no-op and 17 data entries. Five ranked opportunities below. No optimization, benchmark, build, emulator run or speedup claim is part of this read-only research.

## Build and source identity

Kernel commit `291ad9759f7993cb1f96d73bfa1c6f333c2bef34`, tree `8ba32f2153b4716c8cac269bad06a78553f98ded`; public nxdk revision `14d5ee97e73347c973f1f57b68b79ec08c9e77f2`. References below are relative to the permitted kernel source repository. nxdk was used for public ABI/vector context only.

The matched release compile inventory has 569 source entries, checked has 583, including lowercase `.s` assembly. `SARCH_XBOX`, i386, active `NXK_MM_POOL`, `POOLPAGES`, `PHYS`, `VM`, `CACHE`, and FATX write-through apply. Release uses `DBG=0`; checked uses `DBG=1` but **does not enable KDBG or XB_STRACE**. CMake proves the Xbox static HAL includes generic port I/O, PIC and legacy PCI source (`hal/halx86/CMakeLists.txt:68`, `hal/halx86/xbox.cmake:7`). Xbox crypto/loader/SG source is included at `ntoskrnl/CMakeLists.txt:129`; active MM feature options select Xbox replacements rather than unlinked ARM3 implementations. KD selection is at `ntoskrnl/ntos.cmake:466`.

Each ordinal is traced through `xboxkrnl.exe.def`, `ordinals.map`, export generator, actual wrapper/definition and backend. Unmapped symbol-notification exports resolve to generated fatal stubs, even though similarly named RTL functions are compiled. Generated data scaffold remains distinguishable from sized/live data.

## Ranked candidates

The ordering prefers shared impact and bounded proof obligations. Source operation counts are analytical bounds, not measured speedups. All timing recipes require the same compiler, configuration, immutable inputs and guest ISO, at least seven paired trials in alternating baseline/candidate order, all samples retained, median and variation reported. Run actual changed implementations; only a gain exceeding observed variation permits a speed claim. Otherwise report verified work reduction.

### 1. XcpModExp unused final square

**Active locations:** `ntoskrnl/xb/crypto.c:341`, `ntoskrnl/xb/crypto.c:409`, `ntoskrnl/xb/crypto.c:419`, `ntoskrnl/xb/crypto.c:478`, `ntoskrnl/xb/crypto.c:600`, `ntoskrnl/xb/crypto.c:688`. Affected ordinals: 341, 342, 344, 345.

**Avoidable work:** For every ExpBits>0, final Val square and4N-byte copy are never read. Odd path removes one BnMontMul with2N*N 64-bit word products plusN low-word Factor multiplications, carry/reduction/zeroing. Even path removes one BnMulMod withN*N 64-bit products and64N bit-reduction steps. Private CRT reaches two exponentiations.

**Bounded change:** After final accumulator multiply skip square/copy when i+1==ExpBits; keep setup, allocation and result conversion unchanged.

**Correctness:** Prove Tmp/Val/Scratch liveness for odd/even. Retain exponent0, zero modulus, Words bounds, allocation failures, Result/input alias, full output and mutable vector.

**Before/after measurement:** Actual XcModExp Words1,2,32,64,512; exponents0,1,2,3,65537,dense/high-bit; odd/even/zero/modulus1, Base>=modulus and Result aliases. Baseline byte comparison plus independent public big-integer oracle where baseline defined; preserve modulus1 baseline edge if it differs mathematically. Count exactly one square and4N-byte copy removed for nonzero exponent. Exercise public/private blobs, both PKCS#1 prefixes, malformed/out-of-range blobs and invalid padding with unchanged output/return; custom-vector test. Include Words0 and513, allocation-failure injection and unchanged caller output on rejected requests.

**Existing coverage:** Public Xbox API tests are present and wired into tests/xbe/api-regression/Makefile and main.c. tests/xbe/api-regression/xc/rsa.c:122 (modexp_small), :133 (modexp_reduces_base), :143 (modexp_even_modulus), :154 (modexp_identities) and :174 (modexp_rsa_block) check odd/even arithmetic, Base>=Mod, exponent zero, base zero and a 2048-bit signature with exponent 65537. rsa.c:233/:240/:256/:272 checks valid signatures, wrong digests/signatures and a 1024-bit key; :342/:362/:384/:405/:424/:441 checks public RSA output/tail guards, verify equivalence, input range/extra word and key magic. xc/privkey.c:192/:208/:224/:236/:255/:267/:285/:301 covers a 1024-bit CRT roundtrip, output zero extension/guards, unused modulus/private exponent, zero primes, swapped primes, private magic, unrejected modulus-sized input and the extra input word. xc/vector.c:70/:85/:131/:156/:176 checks thunk/vector update/ROM restore/NULL-slot preservation using SHAInit, KeyTable and CryptService. Source coverage was inspected; these tests were not executed in this audit.

**Coverage limit:** Existing direct ModExp cases use a fixed 64-word width, and the CRT key is fixed at 1024 bits. The proposed Words 1/2/32/512 and invalid 0/513 cases, exponent 1/2/dense/high-bit patterns, zero/unit modulus, result/input aliases, allocation-failure injection, malformed PKCS#1 padding and hooks for ModExp/public/private/verify specifically still need targeted coverage. Existing tests do not count the removed final square/copy or provide matched before/after timing; no pass or speed result is claimed.

**Risk/limit:** Low-to-medium: local liveness change, shared RSA/signature impact. No workload frequency or throughput evidence.

### 2. XcpShaLoad buffered-prefix copy

**Active locations:** `ntoskrnl/xb/crypto.c:41`, `ntoskrnl/xb/crypto.c:119`, `ntoskrnl/xb/crypto.c:131`, `sdk/lib/cryptlib/sha1.c:148`. Affected ordinals: 336, 337.

**Avoidable work:** Loads64 buffer bytes; only r=Count[1]&63 live. Remove64-r (1..64) bytes per update/final; load92 ->28+r bytes.

**Bounded change:** Copy only live buffered prefix into local SHA_CTX; keep state/count loads and XcpShaStore writes unchanged.

**Correctness:** Prove A_SHAUpdate fills every byte before transform reads, final fills padding/zeros/reset. Preserve reserved24 caller bytes/inactive buffer tail, count carry, Len0, unaligned data/context, supported aliases and mutable vector.

**Before/after measurement:** Actual XcSHA contexts with canaries, every prior remainder0..63; lengths0,1,55,56,63,64,65,4096,1MiB, split/random updates, offsets0..3 and count carry. Compare whole context after every call, digest/reset and baseline supported input/context/digest aliases. Count load bytes92 versus28+r and identical compression calls; time small versus bulk separately.

**Existing coverage:** Public Xbox tests/xbe/api-regression/xc/crypto.c:39/:49/:60 checks SHA1 abc, empty input and split updates. :166 (sha_context_layout) checks state/count initialization and guards including the 24 reserved bytes; :182 (sha_context_counts_bytes) checks byte counts, a 3-byte buffered prefix and a subsequent 70-byte update crossing a block; :208 (sha_final_reinitialises) checks digest width, context guards/reset and reuse. xc/vector.c:85/:131/:156/:176 checks SHAInit diversion, ROM-vector reporting/restoration, hash after restoration and NULL-slot preservation. These groups are wired into the XBE regression title. modules/rostests/winetests/advapi32/crypt_sha.c:36 additionally covers a core desktop two-update digest. Source coverage only; not executed in this audit.

**Coverage limit:** Existing Xbox tests do not exhaust all buffered remainders 0..63, lengths around 55/56/63/64/65, random split sequences, unaligned contexts/input offsets, count rollover, or complete byte-for-byte tail state against the baseline. Explicit SHAUpdate/SHAFinal hooks and alias cases remain needed. The live-prefix load-byte count and matched guest timing are unmeasured.

**Risk/limit:** Low-to-medium: bounded copy; local uninitialized scratch tail must not be read.

### 3. HalRegisterShutdownNotification fused duplicate/order traversal

**Active locations:** `ntoskrnl/xb/shutdown.c:40`, `ntoskrnl/xb/shutdown.c:51`. Affected ordinals: 47.

**Avoidable work:** Unique registration visits n nodes for duplicate plus p<=n for insertion under spin lock; avoid second p visits.

**Bounded change:** One full membership scan remembers first strictly lower-priority link, finishes duplicate check then inserts. Unregister/drain unchanged.

**Correctness:** Cannot stop at insertion: duplicate later after caller Priority mutation. Do not trust caller links; preserve stable ties, live priority reads, lock/IRQL, late-registration ignore, storage and APC/unwind ownership.

**Before/after measurement:** Actual n0,1,8,64,512 high/low/middle/equal priorities and duplicate storage with changed priority; count n+p ->n and lock-held cycles. Capture callback order; unregister unknown/pending/in callback, late registration, nested power SEH/parking; no duplicate callback/use-after-free. Include negative priorities/LONG_MIN/LONG_MAX and duplicate registrations at every original list position.

**Existing coverage:** Public tests/host/clean-room/shutdown.c:4 includes the actual ntoskrnl/xb/shutdown.c with host shims. :20 exercises unknown unregister with uninitialized links, stable equal priorities, duplicate registrations, removal before drain, callback order, detached-pending unregister, registration ignored during drain, nested/idempotent drains, list cleanup and critical-region/callback-owner balance; :37 checks propagation of an unrelated callback exception with balanced cleanup. tests/host/clean-room/power.c:44 includes actual shutdown/reboot sources; :46 models normal APC suppression while special completions remain possible, and :94 checks nested owner unwind, two callback deliveries, repeated power commands, competing-thread parking and emergency high-IRQL/IF-disabled/APC-level bypass. tests/host/clean-room/run.sh:9/:16 builds/runs these host tests. Source coverage inspected, not executed here.

**Coverage limit:** These are bounded host models with shimmed locks, scheduler/APCs, exception handling and hardware, not actual Xbox guest concurrency/IRQL evidence. Duplicate storage after a Priority mutation, duplicates at every list position, signed priority extremes, larger list sizes and the proposed fused insertion-point traversal still need targeted checks. List-visit counts and lock-held timing, plus guest callback/unregister concurrency, remain unmeasured.

**Risk/limit:** Medium: lifecycle-sensitive and low frequency; time benefit may be immaterial.

### 4. XcpHMAC outer concatenation copy

**Active locations:** `ntoskrnl/xb/crypto.c:160`, `ntoskrnl/xb/crypto.c:182`, `ntoskrnl/xb/crypto.c:183`, `ntoskrnl/xb/crypto.c:185`. Affected ordinals: 340.

**Avoidable work:** Explicit64-byte pad2 copy to temp84 solely concatenates inner digest. Splitting removes64 copy bytes/temp stack bytes but adds one SHAUpdate call.

**Bounded change:** Keep inner digest20, outer update pad2[64] then digest[20]; retain pads/key truncation.

**Correctness:** Preserve Kl>64 truncation, not standard key rehash; empty/NULL-zero segments, aliases/output bytes/reset and mutable vector. No cache/global key retention.

**Before/after measurement:** Actual XcHMAC/NxkHmacSha1 keys0,1,16,63,64,65,128 and segment lengths0,1,55,56,63,64,65,4096 with split equivalence. Compare baseline/public SHA construction with existing truncation, out aliases key/message, unaligned and zero-NULL inputs/custom vector. Count removed64-copy and unchanged compression; time short/long to reject regression from extra call.

**Existing coverage:** Public Xbox tests/xbe/api-regression/xc/crypto.c:106 (hmac_jefe) checks the RFC2202 short-key vector with a NULL zero-length second segment; :119 (hmac_two_segments) checks a two-segment expected digest; :265 (hmac_digest_width) checks that output stops at 20 bytes. These files are wired into the XBE regression title; desktop SHA coverage also exists at modules/rostests/winetests/advapi32/crypt_sha.c:36. Source coverage only, not executed in this audit.

**Coverage limit:** Existing HMAC vectors use 3- or 4-byte keys and short messages: Xbox key truncation above 64 bytes, zero/64/65/128-byte keys, block-boundary/large segments, NULL-zero first/both segments, output aliases, unaligned inputs and explicit HMAC vector hooks still need targeted cases. Tests do not compare the proposed split outer update against the baseline across that matrix or measure compression/copy counts and the extra SHAUpdate call; net time remains unknown.

**Risk/limit:** Low semantic risk; net time uncertain. Accept only work/stack reduction with no representative regression.

### 5. DesLoadKey six-bit reversal

**Active locations:** `ntoskrnl/xb/crypto.c:907`, `ntoskrnl/xb/crypto.c:1100`, `ntoskrnl/xb/crypto.c:1112`. Affected ordinals: 348, 349.

**Avoidable work:** Each decoded DES schedule loops16*8*6=768 bit iterations, triple2304. CBC already decodes once per request.

**Bounded change:** Replace only six-bit reversal loop with independently generated reverse6[64] or proven integer shifts; preserve packed schedule and DesBlock.

**Correctness:** Mask Six low6 bits; exhaustive0..63 proof; retain DES_KEY_SHIFT wrapping, mutable table/unaligned reads, cipher0/nonzero, decryptOp0, in-place CBC feedback/tails/vector. No decoded cache.

**Before/after measurement:** Actual BlockCrypt/CBC DES/nonzero cipher, encrypt/decrypt, lengths0..15,64,4096, in/out-of-place offsets0..3; mutate packed tables for all round/S-box values0..63. Compare ciphertext/plaintext/feedback/untouched tails baseline and public DES/triple known-answer vectors. Count768/2304 ->128/384 lookups; time single versus bulk and record text/rodata (+64-byte table before linker effects). Cipher values0,1,2,MAXULONG and Op0,1,2 must retain default policy.

**Existing coverage:** Public Xbox tests/xbe/api-regression/xc/cipher.c:127/:134/:141 checks exact DES/triple packed schedules and 128/384-byte extents; :152 checks nonzero cipher values 2/0x100 select triple-DES. :166/:181/:196/:210/:224/:244 checks CBC encryption/decryption, final feedback, split-call chaining, zero length, triple-DES and in-place roundtrip. :262/:284/:294 checks single-block known-answer/output extent/decrypt, Op=2 encrypt and triple-DES encrypt/decrypt. xc/align.c:70 asserts aligned CBC input remains intact and expected ciphertext; :88 reports a mod8=4 input/output probe diagnostically and always returns true. xc/vector.c:70/:85/:131/:176 checks KeyTable thunk/diversion, ROM restoration and NULL-slot behavior (the NULL slot is SHAInit). These groups are wired into the XBE regression title. Source coverage inspected, not executed here.

**Coverage limit:** Existing fixtures do not exhaust all 64 six-bit values in every round/S-box, mutate packed tables, vary schedule alignment/offsets 0..3, test every length 1..15/large buffers, check MAXULONG cipher or override BlockCrypt/CBC slots. The misaligned probe is observational and cannot certify correctness or input preservation. Exhaustive reversal equivalence and baseline differential tail/feedback checks remain needed; removed-loop counts, table footprint and matched timing are unmeasured.

**Risk/limit:** Medium: schedule ABI; compiler strength reduction/table footprint may erase time benefit. DesBlock dominates bulk CBC.

## Unranked costs and retained constraints

Name translation (`XeTranslateOa`, `xbe.c:1205`) allocates a prefixed ANSI buffer, copies it and then allocates Unicode. Rename (`XeNtSetInformationFile`, `xbe.c:1994`) allocates Unicode and an inline native rename record. Allocation fusion is plausible but not accepted as a bounded candidate here: prefix-allocation failure falls back to different name/root interpretation, length arithmetic uses USHORT, and rename has distinct allocation-failure statuses. An implementation must establish exact errors and input capture/lifetime before ranking a shortcut. No unchecked name/object cache is proposed.

The current scatter/gather backend uses **one bounce-backed IRP**, not the map comment's per-page I/O. It validates/pins captured page pointers and owns bounce, MDL, references and completion independently. O(Length) copying and temporary storage are real costs, but zero-copy cannot assume arbitrary drivers support noncontiguous MDLs or avoid UserBuffer access. Retain all pins and cancellation/APC ownership.

Hardware leaf exports already use native port-string intrinsics or mandatory volatile MMIO/port cycles. SMBus has bounded idle/completion/retry loops; skipping cycles, changing stalls, caching live device values or weakening hardware ordering is excluded. Device-queue, IRP completion, shutdown critical-region/special-APC and warm-reset ownership remain intact. Native file query paths already have selective position/device/FastIo fast paths. Cache work behind FAT I/O reaches the active Xbox cache backend; this domain does not claim benefits from unused ARM3 code.

Crypto export calls must retain mutable `XcVector` dispatch. Only default backend internals are candidates. Key-table layout, CBC partial blocks/in-place feedback, key truncation and RSA/PKCS#1 validation must remain byte-identical. Internal kernel HMAC calls intentionally use the default implementation rather than the replaceable export vector.

## Coverage gaps and concerns

- `DbgLoadImageSymbols` (7) and `DbgUnLoadImageSymbols` (11) are generated fatal stubs. `IoMarkIrpMustComplete` is a no-op. Default `XcCryptService` returns zero but its export still honors vector overrides. Missing behavior is not counted as optimized success.
- Release `DbgPrint` is a constant-success stub. Checked `DbgPrint` formats/logs and may send debugger output; its transport cost must not be silently removed. `DbgPrompt` returns zero in both matched variants: checked reaches `NxkDebuggerPromptAvailable` (`kd/kdio.c:812`), which returns FALSE without KDBG. Attached debugger input remains unverified. Both matched builds elide XB_STRACE call logging.
- `IdexChannelObject` is a live 264-byte hook/queue/timer object (`xb/ide.c:9`, initialization at84), contrary to the inventory comment describing zero scaffold storage. Native ATAPI driver owns the actual IRQ. Data exports have no per-export callable CPU work.
- Existing limitations include unwired SMC eject counter, incomplete AV controls, missing section-digest verification and async/non-directory-class ANSI directory output. These are behavior gaps, not optimization candidates.
- No product research artifacts, firmware binaries, community archives/disassembly/comparison artifacts or external guest results were consulted. Public test source was inspected without executing tests or treating comments about historical runs as current evidence. The wired XBE xc crypto/RSA/private-key/cipher/vector/alignment groups and actual-source clean-room shutdown/power host tests provide existing coverage, with the precise cases and remaining gaps listed above. Vector hooks cover selected entries rather than every candidate export; the misaligned CBC probe reports observations without assertions. Host APC/lock/hardware models do not certify native title/guest concurrency. Every proposed candidate still requires targeted actual-source/guest regression and matched measurements. Physical hardware,64-MiB support and gameplay gains are unverified.
