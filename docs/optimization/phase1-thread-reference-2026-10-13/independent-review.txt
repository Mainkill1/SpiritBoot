The reference ledger is established from the complete unchanged implementation, not assumed solely from the fixture. ObCreateObject initializes PointerCount 1. PspCreateThread takes 2 keepalives before making the thread runnable. Successful ObInsertObject calls ObpCreateHandle with AdditionalReferences 1, then consumes the initial creation reference. PspCreateThread finally releases its temporary creator reference after KeReadyThread. This leaves1 handle + 1 execution reference. Closing the Phase1 handle leaves execution ownership; the unused extra boot reference had otherwise survived indefinitely. Cid-table entry creation stores the thread pointer but does not add another object reference.

Exit callbacks in PspExitThread run before KeTerminateThread links the object to the reaper. The scheduler queues reaping under dispatcher protection, signals the object and switches away. PspReapRoutine deletes the stack, clears InitialStack, reads the next link and only then drops the execution reference. At final deletion PspDeleteThread therefore does not delete the stack twice; it destroys the CID, removes the remaining ETHREAD process-list entry and drops ThreadsProcess. A callback or another client that takes a legitimate independent reference continues to delay object deletion normally. No raw pointer is retained in the changed boot local.

The handle protects the object if execution/reaping completes before successful create returns or while the handle is closing. The creator's own reference protects the period before its final dereference. For actual UP boot initialization, Phase1 is not scheduled prematurely from the discardable PspInitPhase0 frame: KiInitializeKernel assigns the initial thread HIGH_PRIORITY before ExpInitializeExecutive, runs all Phase0 creation/handle-close work, and only lowers its priority to 0 afterward. The resident Phase1Initialization returns from Phase1InitializationDiscard before freeing INIT. Thread exit/reaper/delete/callback ordering is unchanged and continues in resident code. Thus removing the extra reference introduces neither INIT execution-after-free nor a new callback lifetime edge.
