# Storage behavioral contract

All requirements concern observable outcomes or public boundaries. Internal grouping, data structures, scheduling strategy, and algorithms are the independent implementer's choices.

## Boot, names, and public ABI

**C/R:** Driver registration is in `ntoskrnl/io/iomgr/driver.c:IopFoldedInDrivers`. The creation order is `\\Driver\\Pci`, `\\Driver\\pciide`, `\\Driver\\atapi`, `\\Driver\\Disk`, `\\Driver\\Cdrom`, `\\Driver\\partmgr`, `\\Driver\\MountMgr`, `\\FileSystem\\Xdvdfs`, `\\FileSystem\\Vfatfs`. RAW filesystem initialization precedes this loop. Preserve these names and order. A replacement disk entry may use a newly authored symbol but must remain registered under `\\Driver\\Disk`; optical remains `\\Driver\\Cdrom`. Entries conform to `DRIVER_INITIALIZE`: NTSTATUS return, DRIVER_OBJECT pointer and UNICODE_STRING pointer, NTAPI calling convention on this x86 target. Public callback requirements are documented in [DRIVER_INITIALIZE](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nc-wdm-driver_initialize).

**C/R:** Static enumeration creates the IDE controller stack, queries channel BusRelations, attaches/starts ATAPI on each channel PDO, queries device BusRelations, obtains BusQueryDeviceID, and selects the optical class for an identifier containing `CdRom`; other enumerated devices select the disk class. HDD class Start success precedes partmgr attachment/Start. The tree then queries partmgr BusRelations and starts its partition PDOs. Optical does not receive partmgr attachment. A class FDO must attach to its supplied PDO stack and support the boot START request with valid resource-list lifetimes. This is a fixed Xbox topology, not registry-driven desktop enumeration.

**C/R:** PDO device nodes are prepared by the existing kernel before class attachment. Their existing public kernel fields support started-state and device-interface callers; the replacement does not require or recreate any private class layout. The boot path references the root device-node PDO through power initialization. `ntoskrnl/include/internal/nx-devtree.h` is the local static-tree declaration boundary.

**C/R:** Preserve `\\Device\\Harddisk0\\Partition0` for raw HDD and `\\Device\\CdRom0` for optical. Existing partmgr publishes `\\Device\\Harddisk0\\PartitionN` links for discovered FATX partitions. Optical also has `\\DosDevices\\CdRom0`. The XBE loader tries `\\Device\\CdRom0\\default.xbe` and the dashboard path `\\Device\\Harddisk0\\Partition2\\xboxdash.xbe`. Preserve device numbering/counts, stack size, direct-I/O behavior, lower alignment requirement, valid VPB association, and device types FILE_DEVICE_DISK / FILE_DEVICE_CD_ROM. Optical characteristics include read-only and removable media.

**C/R:** Runtime dispatch code/data/callbacks must remain resident. The composed kernel seals boot-only PnP before INIT discard: Disk and Cdrom are included in the sealed-name list, post-boot PnP is changed to invalid-device-request dispatch, and AddDevice is cleared. Replacement integration must not leave a runtime pointer into discarded INIT pages. Boot-created devices must have DO_DEVICE_INITIALIZING cleared before ordinary requests arrive. Failed registration, allocation, attachment, or Start must yield a bounded failure and release resources whose ownership has actually ended. Exact baseline startup failure statuses are **U**.

## Request results and lifetime

**R/P:** A caller sees exactly one terminal parent IRP completion. Final IoStatus.Status, IoStatus.Information, event/IOSB delivery, APC behavior, and completion priority must describe the parent request. Dispatch return status is distinct from terminal result. Lower completion may occur before IoCallDriver returns or after it returns STATUS_PENDING. Once pending is exposed, it remains consistent with I/O-manager pending semantics. No request, callback context, SRB, pinned page, partial MDL, or device state may be used after its ownership ends. Completion may occur at DISPATCH_LEVEL; callback state needed there must be resident. See [completion semantics](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/implementing-an-iocompletion-routine) and [callback registration](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-iosetcompletionroutine).

**C/R:** Lower IRP_MJ_SCSI consumes the legacy SRB through the stack's Scsi.Srb field and requires Srb.OriginalRequest to identify that same child IRP. It obtains the MDL from that IRP, takes the data-range address from Srb.DataBuffer, and uses Srb.DataTransferLength in bytes. Those objects and their backing memory remain valid throughout lower queuing, DMA/PIO, autosense/recovery, and completion. DataBuffer must describe the requested subrange within the MDL's virtual-address domain; a distinct mapped system address is not automatically interchangeable. Lower PIO computes an offset from the MDL's starting virtual address. See [MDLs](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/using-mdls).

**C/R:** Actual lower transfer bytes are reported in child Irp.IoStatus.Information. The inspected pending completion path does not write its actual length back to Srb.DataTransferLength; do not mistake the SRB's original input count for bytes transferred. DATA_OVERRUN can indicate a short reply. An actual count greater than the submitted segment is invalid. Zero-length requests perform no data command. Nonzero successful data I/O must not silently fabricate bytes absent from lower completion.

**R:** Borrow the I/O-manager-owned parent IRP, original MDL, caller buffer, upper file/device references, and FATX lease for their existing lifetimes. The class must not free the parent's MDL or revoke the FATX lease while a lower request still uses it. Newly allocated child IRPs, partial MDLs, SRBs, sense buffers, and state have exactly one cleanup owner. If a completion handler frees an allocated child IRP, it must prevent I/O-manager continuation through freed storage; the public completion-stop contract is STATUS_MORE_PROCESSING_REQUIRED. Cancellation, issuer exit, close, truncate, delete, teardown, mapping failure, and every allocation failure must preserve these lifetimes. An ownership table is required as implementation evidence, but this spec imposes no private layout.

**R:** Segments must respect adapter maximum bytes, physical-page count, alignment, CDB addressing/count limits, and ATA limits. A long sequence of inline-completing segments has bounded kernel stack usage. Do not add a mandatory worker round trip, unnecessary bounce copy, command, clock sample, or allocation to a healthy transfer. Existing FATX direct reads and IRP-owned leases are performance requirements. HDD and DVD sharing a controller must retain lower queue progress; class-level serialization of all outstanding traffic is not justified by this contract.

## Actual composed lower commands and limits

**C:** Legacy SRB functions recognized on Xbox include EXECUTE_SCSI, CLAIM_DEVICE, RELEASE_DEVICE, LOCK_QUEUE, UNLOCK_QUEUE, RELEASE_QUEUE, FLUSH_QUEUE, QUIESCE_DEVICE, FLUSH, and SHUTDOWN. Unknown functions are rejected. FLUSH_QUEUE is queue cancellation/release, not device-cache durability. Lower fills PathId/TargetId/Lun for execution and clears SrbExtension for its own transport use. Own uninitialized SRB scratch must not masquerade as lower internal state.

**C:** ATA HDD accepts INQUIRY, TEST UNIT READY, MEDIUM REMOVAL, START STOP UNIT, REQUEST SENSE, READ CAPACITY(10), READ CAPACITY(16) through its service action, READ/WRITE(6), READ/WRITE(10), READ/WRITE(12), and SYNCHRONIZE CACHE(10)/(16). Under SARCH_XBOX, READ/WRITE(16), VERIFY(10)/(12)/(16), MODE SENSE/SELECT, ATA PASS THROUGH, and REPORT LUNS are compiled out. Do not submit those unsupported HDD commands as a compatibility shortcut. READ CAPACITY(16) availability does not imply READ(16) availability.

**C:** HDD read/write addressing comes from the CDB, while the translated ATA sector count comes from the submitted byte count rounded by sector size. The replacement must submit sector-aligned lengths and consistent CDB counts. 32-bit LBA limitations of supported READ(10)/(12) remain relevant even when ATA can address 48-bit sectors. Default PATA transfer limit is 0x20000 bytes (128 KiB); negotiated adapter limits, physical-page limits, and lower alignment remain authoritative. Capacity is derived from actual device/media response, not fixed test-image size. The conventional FATX HDD sector size is 512 bytes. Reject unrepresentable capacity/range arithmetic before lower submission.

**C:** ATAPI optical packets are passed through to the drive; the software switch is not a proof that a particular physical drive implements every CDB. Required optical operations are READ(10), READ CAPACITY, READ TOC, TEST UNIT READY, and bounded sense/media handling. Direction flags must reflect actual data movement. READ(10) is eligible for packet DMA; no-data and some control CDBs need not use DMA. The lower already handles odd DMA-buffer addresses through an existing PIO fallback where supported; preserve title buffer behavior instead of assuming all caller pointers are word-aligned.

**C/R:** SRB_FUNCTION_FLUSH and SHUTDOWN themselves return success without issuing hardware cache synchronization. PATA clears read/write FUA. Therefore successful FUA-marked writes or SRB flush are not proof of durable storage. SYNCHRONIZE CACHE is the separate ATA cache-flush route. That route returns success without hardware command if volatile cache is disabled or no flush command is selected; otherwise it issues the selected flush command and returns its eventual outcome. Replacement flush success requires ordered prior writes and verified cache-sync completion, or independent proof that volatile caching is disabled. Unsupported flush capability with enabled cache is a visible qualification gap, not proof of durability. Preserve metadata/data ordering and report device flush errors. Independent physical durability remains **U**.

## Errors, autosense, and queue recovery

**C:** Ordinary lower completion maps base SRB_SUCCESS to STATUS_SUCCESS, TIMEOUT to STATUS_IO_TIMEOUT, NO_DEVICE to STATUS_DEVICE_DOES_NOT_EXIST, DATA_OVERRUN to STATUS_BUFFER_OVERFLOW, SELECTION_TIMEOUT to STATUS_DEVICE_NOT_CONNECTED, and other listed/unlisted failures to STATUS_IO_DEVICE_ERROR. Exhausted lower allocation may instead yield SRB_INTERNAL_ERROR plus InternalStatus/IOSB STATUS_INSUFFICIENT_RESOURCES. Queue-admission cancellation can yield STATUS_CANCELLED; removal/admission and remove-lock failures can yield STATUS_NO_SUCH_DEVICE. Keep these paths distinct. Public SRB modifier bits must be separated from the base status; see [legacy SRB interface](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/srb/ns-srb-_scsi_request_block).

**C:** Lower already requeues busy work, retries resource rejection once using its own per-SRB tracking, and has error-recovery retries for timeout, reset, sense failures, and paging I/O. A final failure may freeze the device queue and set SRB_STATUS_QUEUE_FROZEN unless NO_QUEUE_FREEZE was requested. Normal requests then wait; RELEASE_QUEUE releases error freeze, while UNLOCK_QUEUE releases lock freeze. Bypass flags only bypass their corresponding queue condition. Other frozen/removal states are not universally bypassable.

**R:** A failed request must not strand later unrelated work. Recovery must have bounded resources and work limits even under pool exhaustion. Do not add indefinite class retries on top of lower retries or blindly repeat writes with uncertain completion. Lower can keep the same SRB/IRP pointer across internal requeue; that does not mean terminal completion occurred or that memory can be reclaimed. Mixed HDD/DVD requests after a queue failure must complete or obtain an explicit bounded terminal result.

**C/R:** Supply an owned resident sense buffer if autosense is required. Inspected lower autosense paths use a nonnull supplied buffer and length; they do not promise to allocate that buffer merely from a legacy allocation flag. They return AUTOSENSE_VALID only with bounded copied sense data. Do not read sense fields absent from returned/allocated length or interpret malformed data as a valid error. Exact upper-class mapping for no-media, unit attention, not-ready/spin-up, illegal request, and data protection is **U** as baseline observation; use documented public media semantics and independently test each candidate policy.

## Required control outcomes

All successful control responses initialize every returned byte and never write beyond OutputBufferLength. Rejected requests transfer zero bytes unless a public descriptor-size response explicitly requires bytes. Buffered IOCTL data is at SystemBuffer. Numeric sizes below are this x86 interface's ordinary layouts and must be asserted against actual build declarations.

| Operation | Required outcome / bytes | Evidence and qualification |
| --- | --- | --- |
| HDD STORAGE_GET_DEVICE_NUMBER | success, 12 bytes; FILE_DEVICE_DISK, disk number 0, raw partition number 0 | C/P: partmgr Start requires device number; raw partition number is R pending black-box check |
| HDD DISK_GET_DRIVE_GEOMETRY | success, 24 bytes; valid sector size and media geometry | P/R; exact baseline cylinder/head/track convention U |
| HDD DISK_GET_DRIVE_GEOMETRY_EX | accept 32-byte base or larger; return initialized geometry + 64-bit exact byte length, at least 32 bytes on success | C/P/R: partmgr refresh demands it; do not use sizeof(Data[1]) padding as the minimum. Optional extended metadata length policy needs an explicit candidate rule and parity check |
| HDD DISK_GET_LENGTH_INFO | success, 8 bytes exact capacity | P/R; too-small buffer STATUS_BUFFER_TOO_SMALL, zero bytes |
| Optical CDROM_GET_DRIVE_GEOMETRY | success, 24 bytes; sector size from valid media capacity response (normal DVD 2048); short output STATUS_BUFFER_TOO_SMALL, zero bytes | O/P; geometry when no capacity response U |
| Optical CDROM_READ_TOC | require output >=804 bytes, issue format-0/LBA TOC query capped to 804; valid short lower reply is success with actual bytes | O/P: null/short output STATUS_BUFFER_TOO_SMALL, zero bytes; preserve lower errors except expected short DATA_OVERRUN |
| Optical CDROM_READ_TOC_EX | STATUS_NOT_IMPLEMENTED, zero bytes | O compatibility requirement |
| CDROM_CHECK_VERIFY / STORAGE_CHECK_VERIFY | TEST UNIT READY/media check; no optional output => zero bytes; successful optional count => ULONG / 4 bytes; nonzero output shorter than 4 => BUFFER_TOO_SMALL/0 | O/P/R; exact baseline media-change count U |
| STORAGE_QUERY_PROPERTY | retain lower StorageDeviceProperty, StorageAdapterProperty, alignment queries where demanded; validate input and preserve lower descriptor negotiation | C: existing lower supports these, unknown IDs/queries retain lower rejection policy |
| IRP_MJ_FLUSH_BUFFERS / SHUTDOWN on HDD | ordered cache synchronization, zero data bytes, actual error propagation | C/R; no success-only SRB shortcut |
| Write to optical | STATUS_MEDIA_WRITE_PROTECTED, zero bytes and no lower write | O/R |
| Misaligned/negative optical read | STATUS_INVALID_PARAMETER, no lower data request | O/R |
| Unsupported control / data operation | explicit bounded failure with zero unwritten bytes, preferably documented invalid-device-request policy | R; exact old generic fallback statuses U |

Public support: [device number](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddstor/ni-ntddstor-ioctl_storage_get_device_number), [geometry](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntdddisk/ni-ntdddisk-ioctl_disk_get_drive_geometry), [extended geometry](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntdddisk/ni-ntdddisk-ioctl_disk_get_drive_geometry_ex), [length](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntdddisk/ni-ntdddisk-ioctl_disk_get_length_info), [TOC](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddcdrm/ni-ntddcdrm-ioctl_cdrom_read_toc), [media verification](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddstor/ni-ntddstor-ioctl_storage_check_verify).

**C:** Current lower property queries reject too-small input with BUFFER_TOO_SMALL; unsupported query type with NOT_SUPPORTED; an output smaller than STORAGE_DESCRIPTOR_HEADER with INFO_LENGTH_MISMATCH; a sufficient header-only output succeeds and reports required descriptor size. PropertyExistsQuery succeeds for supported properties without a full response. Keep those transport-facing outcomes available rather than fabricating new adapter descriptors.

**P/R:** On detected media change with a mounted VPB, CHECK_VERIFY requires STATUS_VERIFY_REQUIRED/0 and volume-verification indication; an unmounted media-change check reports a device error/0. Other failures return zero bytes. This published requirement is not claimed as observed Xbox baseline behavior.

## Partition and optical end-of-media behavior

**C:** Existing partition manager owns partition enumeration, per-partition byte-offset translation, geometry metadata above the class, mountdev name/unique ID, and volume links. Its Start needs STORAGE_GET_DEVICE_NUMBER. BusRelations refresh needs GEOMETRY_EX and reads partition information through existing kernel partition APIs. On Xbox those APIs probe fixed FATX superblock offsets using ordinary 512-byte reads, not an on-disk MBR/GPT. Do not recreate partition synthesis in the class. Partition read/write already adds the partition offset; the raw class receives absolute disk offsets and must not add it twice. Flush/shutdown from a partition routes to raw class beneath partmgr.

**C:** For a fully formatted canonical image, retained partition order is E/data, C/system, X/cache, Y/cache, Z/cache. The current probe enumerates only FATX-bearing extents and assigns dense discovered numbers; behavior when an earlier expected FATX extent is missing needs an independent compatibility decision. Desktop partition writes and surface VERIFY are not required by observed Xbox boot paths and are compiled out in several retained paths; do not claim them as supported merely because public IOCTL numbers exist.

**O/R:** Sector-aligned optical requests with nonnegative offset are not rejected solely because offset+length crosses advertised media length. Page-rounded tail reads must reach the lower device, retaining actual data/byte/status outcomes. Do not fabricate success, pad bytes as if hardware returned them, or use HDD end-of-disk policy for optical. Current XDVDFS itself uses sector rounding and partial-sector bounce reads, not a cache-manager file path; page rounding is still a required optical class compatibility scenario from the existing optical contract. Exact no-disc/cross-boundary raw-read outcomes are **U** until independently measured.
