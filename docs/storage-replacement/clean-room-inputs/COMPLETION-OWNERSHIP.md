# Exact target completion and reuse contract

Frozen against the composed baseline identified in README, 2026-10-14. **C** = read from retained compatible target source; **P** = published API contract; **I** = inference requiring candidate proof; **U** = unmeasured/unknown. No native execution or candidate lifetime validation is claimed here.

## Ownership boundary

**C:** The target I/O manager invokes the registered completion callback, then checks its returned NTSTATUS. If the result is STATUS_MORE_PROCESSING_REQUIRED, it returns immediately without subsequently reading or writing the child IRP, its stack locations, or its MDL. Its normal MDL/IRP/APC/event completion machinery is bypassed for that invocation. A different callback return value continues completion and does not grant this reclamation boundary.

**C:** IofCallDriver dispatches the lower callback and returns its status without later inspecting the dispatched IRP. In the inspected ATAPI terminal execution path, child IOSB/SRB/sense results and transport resource release precede IoCompleteRequest. That path does not dereference the old child IRP, SRB, sense buffer, or partial MDL after IoCompleteRequest returns. The completion-DPC caller has already preserved its list successor; subsequent DPC bookkeeping does not read that child's storage. Inline rejection/queue-control dispatches subsequently release the lower device remove lock using the saved IRP address as an opaque tag; the remove-lock code compares the tag, not IRP contents. Device state is still accessed in that epilogue.

**C:** The Xbox finish bridge continues shared channel/generation bookkeeping after its lower completion operation. It does not dereference child IRP/SRB/sense storage there. Its generation guard handles a new command using the same IRP address; pointer equality alone is not a completion-generation boundary.

**I/R:** Therefore, these inspected target paths permit a completion routine returning STATUS_MORE_PROCESSING_REQUIRED to reclaim or reuse its own child packet/transport buffers before that callback returns, provided the adapter itself and every still-active older frame no longer access those old contents. There is no automatic requirement to keep the child packet until callback return merely for the I/O manager. This is conditional permission, not proof that a specific transport pump is safe.

**R:** A callback can initiate another command, receive repeated inline completions, and cycle through transport storage before its original invocation unwinds. Two storage banks do not prove ownership; an old callback may still hold a bank address after both banks have been reused. Candidate evidence must identify every read/write performed after reentry, every still-active submission frame, and the ownership of callback contexts, status/byte snapshots, SRBs, sense buffers, MDLs, request state and device references. No older frame may interpret a newer generation as its own. Final parent completion can itself invoke upper code that releases request memory; candidate code must likewise prove its remaining frames do not touch that memory.

**R:** Device/reference lifetime extends through active submission and callback frames, including lower device/remove-lock and shared-channel epilogues. The ability to reclaim a child IRP does not permit destroying its lower device while IoCallDriver or a completion/bridge operation still uses that device. Cancellation or teardown does not shorten active DMA or device-reference lifetime.

## Reinitialization and cleanup

**C/P:** IoAllocateIrp allocates nonpaged driver-owned IRP storage, initializes it, and does not queue it to a thread. Stack count must cover the lower stack; allocation may return NULL. An allocated child must have a completion owner for success, error and cancellation. Use of a builder that attaches the IRP to I/O-manager/thread completion changes ownership and is not the same reusable-child contract. [Allocation API](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-ioallocateirp).

**C/P:** IoReuseIrp requires no installed cancel routine and no thread-list association. It reinitializes the entire packet and preserves its allocation bookkeeping; MDL pointer, stack/callback/context, byte/status and cancellation fields are not carried into a new operation automatically. Previously owned MDL/sense resources are not freed by reinitialization. Only driver-allocated/raw-owned IRPs qualify for reuse; caller IRPs and the synchronous/device-control/associated builder cases do not. [Reuse API](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-ioreuseirp), [reuse restrictions](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/reusing-irps).

**C/R:** IoFreeIrp frees packet storage without freeing its attached MDLs. Candidate cleanup must separately dispose of its own partial MDLs and mappings, while leaving borrowed parent MDL/pages to the upper owner. IoFreeMdl prepares a partial MDL for reuse/unmapping before freeing the descriptor. A reused partial MDL must not abandon a separately created system mapping. Its virtual-address range remains a proper subset of the original pinned MDL; a mapped system alias is not automatically the source-MDL address required by the lower PIO offset contract. [Partial-MDL API](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-iobuildpartialmdl).

**C/P:** IoSetCancelRoutine exchanges the callback address atomically and returns its previous value. A NULL result can mean no previous callback or cancellation already owns it; it does not prove the cancel callback has returned. IoCancelIrp sets Cancel even when it returns FALSE; that FALSE is not terminal completion. Cancel callbacks run at DISPATCH_LEVEL with the system cancel lock held and must release it. Do not reuse/free child storage before both lower ownership and any cancel-callback ownership are reconciled. [Cancellation registration](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-iosetcancelroutine), [cancel request](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-iocancelirp).

**U:** No claim is made for arbitrary third-party lower drivers, title-replaced mutable IDE hooks, SMP variants, active cancellation races in candidate code, candidate bank reuse, or teardown not present in the inspected ordinary boot-lifetime path. These require bounded candidate tests and review.

## Required additional candidate checks

Use a deterministic lower double implementing the target reclamation contract, not one that illegitimately reads a freed child after returning from its own completion call. Test a genuinely asynchronous completion that initiates a long run of inline child completions before its original callback returns. Prove no active older callback/submission state is reread after recycling and that call-stack usage remains bounded. Repeat with inline terminal failure, parent completion freeing request context, cancellation ownership crossing completion, lower same-pointer requeue, partial-MDL mapping, and device teardown while dispatch epilogues remain active. A passing two-bank alternation count alone is insufficient.
