## Native ownership and completion

Reserve device/slot/envelope storage, child IRPs sized for the attached lower stack, SRBs, resident sense, bounded control buffers and recovery capacity at setup. Select slot count from P1 workload/footprint requirements, not an invented constant. Healthy data preparation and RELEASE_QUEUE must not allocate, bounce-copy, sample clocks or require a worker. Setup failures unwind only acquired resources in reverse order; slot exhaustion gives bounded failure. Keep HDD/DVD admission independent and retain lower concurrency.

| Object | Ownership end |
| --- | --- |
| Parent IRP, original MDL/pages, caller buffer, upper FATX lease | Borrowed through final parent delivery, after lower ownership and cancel ownership end. Never free parent MDL or release the upper lease locally. |
| Adapter envelope and by-value handle/token/result | Adapter-owned and resident through dispatch, submit, completion, cancel and parent-completion epilogues; parent completion may immediately free parent memory. |
| Child IRP/SRB/sense and optional partial MDL | Adapter-owned per live transaction; one retire after terminal report and submit return, plus adapter cancel-frame ownership. Internal requeue is not terminal. |
| Device/lower references and pool | Admission sealed, pending requests drained, whole calls/callbacks and lower epilogues drained, all callback/cancel sources fenced before destruction. |

`prepare` resets an idle driver-owned IRP with no installed cancel routine/thread association, installs fresh stack/callback/context/MDL state, initializes the entire SRB, and sets Scsi.Srb and Srb.OriginalRequest to the matching child. DataBuffer is the original MDL virtual-domain subrange; mapped system aliases are not interchangeable. Validate page and byte bounds, negotiated alignment, READ(10) range and sector/count consistency. Borrow the original MDL where the lower contract permits; introduce partial MDLs only with proved sizing, mapping cleanup and reuse. Never reuse a mapped partial descriptor by merely clearing flags.

`submit` calls IofCallDriver once. The child completion copies token, terminal IOSB status/Information, base SRB status, modifier flags and bounded sense before calling the core, then returns STATUS_MORE_PROCESSING_REQUIRED without touching child/old slot contents. Submit return is not terminal proof. Inline results retire after submit returns; an asynchronous callback may run an inline chain, so all old frames must avoid recycled storage. Do not substitute a two-bank argument for this proof.

`enter/leave` use a short resident lock with correct saved IRQL. `mark_pending` is a nonblocking nonreentrant leaf under that lock. All lower calls, completion and cancellation occur outside it. Map terminal native failures into disjoint negative adapter results; preserve timeout, device absence, cancellation and resource errors. Count actual child IoStatus.Information, never the submitted SRB length. Reject over-reporting; preserve bounded verified partial data under the core's explicit policy. Freeze the native status map for core short/protocol/durability errors before tests; do not claim historical parity for those choices.

Install parent cancellation using the admitted atomic callback and cancel-lock semantics. The envelope bridges cancellation that arrives before nx_start publishes its handle: latch intent, publish the handle under synchronization, then deliver cancellation once if still active. Keep dispatch/cancel references through this handshake even if nx_start completes inline. Terminal ownership removes the cancel callback under the same protocol and waits for an already-owning cancel frame; NULL removal and IoCancelIrp(FALSE) are not drain evidence. Release the system cancel lock before entering the core or calling lower. The port cancel operation holds a child/envelope reference across IoCancelIrp and any inline callback; retirement cannot recycle it until that frame stops using it. Record a lock-order table and prove no cancel-lock/core-lock inversion.

Hold a whole-call reference around nx_start/nx_lower_done/nx_cancel and every external callback; pending intervals also own references. Zero active slots is insufficient because the pump continues after parent completion. Removal/start failure seals admission and drains; a broken lower that never terminates cannot justify freeing live DMA storage or fabricated completion. Ordinary boot-fixed lifetime may keep devices resident; teardown tests must still prove all implemented cleanup paths.

## Bounded disk and optical controls

Create an internal control transaction with copied CDB (up to the legacy SRB's declared capacity), checked CDB length, explicit direction/extent, resident buffer/MDL ownership, timeout, supplied sense bound and copied terminal IOSB/SRB outcomes. It has one in-flight command, finite state transitions and no automatic uncertain-write retry. Choose concrete timeout/sense/retry limits from target lower/public facts before implementation acceptance; finite fields alone do not establish termination. Pool exhaustion must not prevent the single queue-release recovery step; failed recovery fails/quarantines affected work within the same ownership rules. Zero-data commands use no data transfer. Export no general caller-provided CDB interface.

The initial operation list is finite:

* READ CAPACITY(10), plus supported READ CAPACITY(16) only when needed to resolve capacity, with checked big-endian response length, last-LBA-plus-one multiplication and signed capacity bounds. READ(16) remains unsupported on HDD. Query validated adapter byte/page/alignment limits. Do not adopt the request test's ATA block limit as hardware discovery.
* Optical READ TOC format 0/LBA: output minimum 804, command and transfer capped at 804, actual bounded short reply with expected DATA_OVERRUN becomes success; do not claim untouched bytes. TOC_EX returns NOT_IMPLEMENTED/0.
* TEST UNIT READY for verify: no output gives 0; optional successful count gives 4; nonzero output below 4 fails. Bounded sense parsing distinguishes no-media, not-ready, unit attention and protection under a frozen candidate mapping. Mounted media change gives VERIFY_REQUIRED/0 and volume-verification indication; unmounted change gives device error/0. Change-count policy remains explicit candidate policy until observed.
* Basic HDD/optical geometry is 24 bytes from validated capacity and explicit CHS policy; HDD length is 8, device number is 12 (disk 0/raw partition 0), raw extended geometry has a 32-byte minimum with an explicitly initialized tail policy. Reuse the composer if optional tails are supplied; never fabricate partmgr identity in the raw class. Preserve the retained owner's actual MBR style/signature, not stale prose suggesting BRFR output. Retained partmgr geometry uses its existing owned adapter/composer and measured prefix policy.
* Forward supported lower property queries with their descriptor negotiation and terminal ownership intact. Install the cache property hook only in its lower PDO owner; it returns status/Information and never independently completes/forwards. Optical writes fail write-protected; negative/misaligned reads fail; aligned optical tails crossing capacity reach lower and retain actual bytes/errors.
* HDD flush/shutdown and write-through route through NX_FLUSH/NX_WRITE_THROUGH, preserving barriers and actual sync errors. No SRB_FUNCTION_FLUSH/SHUTDOWN or FUA durability shortcut. Keep ordinary data operations in the request core.

Capacity/media configuration is immutable inside a live nx_device. Optical media changes seal admission, drain old transactions and rebuild the configuration before new-media data; no in-place mutation of core fields. Empty-drive startup must leave the optical namespace usable for TUR/capacity controls without inventing media geometry. Keep this transition local to optical, not a global HDD/DVD lock.

The disk class receives START before partmgr attachment and receives a second forwarded START afterward. Do not retain temporary resource pointers after their caller-owned lifetime. Boot never requires a class private extension. The listed Disk/Cdrom PnP dispatch and AddDevice pointers are sealed before INIT discard; runtime transport/cancel/control code remains resident. These facts close the boot resource orchestration question.

The narrow admitted lower claim/release read shows: RELEASE clears DeviceClaimed and succeeds; CLAIM when already claimed returns DEVICE_BUSY/SRB_BUSY; successful CLAIM sets DeviceClaimed and returns the PDO pointer in Srb.DataBuffer. This is a claim-result pointer, not transfer bytes or evidence of an acquired object reference. The handler is pageable. Choose one claim during passive setup, record ownership only after success, and release only a claim this instance owns during failed setup/cleanup. Repeated START does not claim again. This is an explicit candidate ownership policy; the inspected handler alone does not establish that every data command requires claiming or impose a legacy class decomposition. Native setup tests cover busy claim, successful claim plus later failure, one release, and repeated START.
