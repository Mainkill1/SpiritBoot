# Read-only Windows DVD method preparation

Status: source and portable host checks only. The native Windows PowerShell5.1
DVD method has not run, and this work supplies no performance or driver result.

The runner passes typed QMP arguments literally. The Windows method therefore
freezes an absolute target path from the exact owned package before launch.
The guard checks that package against the actual input manifest and verifies
the uniquely observed removable, unlocked, raw, read-only DVD before and after
the runner's declared change. It opens no monitor connection itself. A device
name is a declared hypothesis until the actual initial query proves it.

The guard binds the protected pipe's user/session/ACL/handshake receipts to
actual wrapper, client, server and guest process ancestry, creation times,
executable/command and local monitor ownership. Its process queries use the
documented [Win32_Process](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-process)
fields and SID method; listener ownership uses
[Get-NetTCPConnection](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-nettcpconnection).
Unavailable or changed observations fail and preserve the partial receipt.

The separately pinned module is loaded through a short ordinary inline
PowerShell command after hashing the same source bytes it will execute. It
changes no execution policy. Hashing files and checking typed raw recipes
happen outside any accepted timing measurement. Recursive JSON duplicate
rejection precedes decoding, and a property wrapper preserves one-element
top-level arrays on the older PowerShell pipeline. Source and recipe artifacts
must be included in the native freeze.

Six portable PowerShell7.4.6 checks exercise the actual functions and main
routine with explicitly invented process/desktop inputs: duplicate and invalid
JSON, foreign/ambiguous/writable DVD routes, process/listener mismatch,
initial/final lifetime change, failed managed results and differing module
bytes. They qualify these control decisions only. Actual Windows CIM behavior,
desktop context, process lifetime and recorder data still require a native run.

Runtime working directory and NTFS file IDs remain unobserved. The receipt
reports path, size, timestamps and SHA256, and labels the existing server's
declared working directory as construction evidence. The absolute target
avoids relying on a live working-directory assumption. The existing generation2
recorder exits shortly after END; a separate source/binary variant needs an
explicit untimed grace period so actual live final observations can finish.
An expired process or cancelled guard remains failure, never inferred success.
