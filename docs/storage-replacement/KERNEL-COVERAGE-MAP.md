# Kernel test-source coverage map

The machine-readable [inventory](../../sources/kernel-coverage-report.json) enumerates all 371 declarations in the selected Xbox export definition: 337 callable exports and 34 data exports. It does **not** establish that the entire kernel is covered or that any particular export executed. Its native-execution count is deliberately zero: no native execution receipts are imported by this tool.

The pinned [inputs](../../sources/kernel-coverage-inputs.json) identify the actual CC0 export-definition bytes, public test sources first pinned from reference tree `7e891ec86f42b1313e5cd3453347836ac451ba79`, product-owned XBE sources and independently owned replacement specifications/patches. Those selected source bytes are unchanged in the exact final assembled tree `2f6790bae801075928f1ff556aed1ef2d2938858`, which CI supplies and verifies separately before running this inventory. The byte pins do not by themselves establish whole-tree composition, current candidate linkage or native execution. Source paths are relative to the separately supplied assembled checkout or this product; no investigator filesystem paths or excluded driver bodies are exported.

## What each level means

| Level | Evidence | What it does not prove |
| --- | --- | --- |
| `direct_invocation` | An export name followed by call syntax inside an ordinary C test-function body, outside an unresolved conditional region | Compiler symbol binding, registration/reachability, actual execution, correctness of every branch or native performance |
| `symbol_reference` | A C identifier reference, including address-taken/data/conditional/member or declaration-like occurrences | A call or executed behavior |
| `manual_contract` | An explicitly associated, hash-bound specification and test source | Automated call reachability, executed assertions or native installation |
| `untested` | No evidence in this pinned source inventory | That no test exists elsewhere |

The strongest available source level partitions the 371 exports; the report retains every individual source/line/function reference. Multiple sites and repeated test copies are not added as independently covered exports. Six internal replacement contracts are listed separately because export coverage does not describe their internal ownership and completion invariants.

This report currently finds 320 exports with direct-call syntax, 1 export with a manual assembly-call contract, 39 with references only and 11 with no source evidence. These are source-inventory counts, **not 321 tested implementations**. Manual contracts contribute no native-execution credit.

The lexer removes comments and string/character contents, ignores preprocessor directive bodies, distinguishes ordinary function bodies from prototypes/definitions, and avoids promoting member calls or data exports to direct calls. It downgrades every conditional region because it does not infer compiler flags. It is deliberately not a C compiler: macro expansion, local shadowing, pointer targets, includes, assembly calls and semantic call graphs remain unresolved. An apparently direct call may therefore still require compiler/linker inspection. Malformed delimiters/literals, unsupported source languages, missing/changed/unsafe/duplicate input descriptors, export identity/count mismatches, and unbound manual contracts reject generation rather than silently producing partial coverage.

## Reproduce and check

From the product root, supply the exact final assembled source checkout. CI also verifies its tree as `2f6790bae801075928f1ff556aed1ef2d2938858`:

```sh
python3 tools/kernel_coverage.py --source-root /absolute/path/to/final-assembled-source
python3 tools/kernel_coverage.py --source-root /absolute/path/to/final-assembled-source --check
python3 -m unittest discover -s tests/host -p 'test_kernel_coverage*.py' -v
```

Generation writes the report only after every input verifies and analysis succeeds. `--check` compares deterministic generated bytes with the checked-in report and does not update it. There is no timestamp in generated output. The semantic input-manifest digest hashes canonical JSON; source descriptors retain exact raw-file SHA256s. Updating source pins is an explicit reviewed change, not a fallback accepting whatever checkout happens to exist.

The host tests include ABI declaration parsing, duplicate/malformed exports, comments/literals/prototypes/member false positives, disabled conditional calls, function-pointer and data references, malformed C, missing/modified/traversing/duplicate inputs, manual execution-promotion refusal, and deterministic report generation. Python host invokers are syntax-checked and used only as manual links; strings resembling C calls earn no credit.

## Broad suites and before/after extraction

CI wires the broad API regression, 23 clean-room checks, 7 warm-reset checks, 41 kernel-performance workloads and 31 additional native fixtures with 5,481 declared assertions. These catalogue numbers overlap implementations and are not a coverage percentage. The separately pinned older XISO catalogue has 144 executable leaves plus 5 structural groups. Historical final-memory results describe 634 enabled API leaves on their own dated images. Neither number is the 36-case storage matrix.

The storage matrix separately exercises small reads, two FATX sequences across queue depth/pressure/cache conditions, write/API-flush/reopen, scatter/gather boundaries and both optical payloads. Existing reference-ROM functional/diagnostic results do not supply a post-extraction candidate comparison.

The final pre-extraction [broad XISO ABBA run](BROAD-XISO-FINAL-COMPARISON.md)
completed every one of the 144 leaves twice on each BIOS. All four runs passed
their 149 applicable records and the two SpiritBoot runs repeat exactly, but
one Complex framebuffer observation did not repeat. Its frozen comparison
therefore remains FAIL and its two-run timings remain descriptive. This result
does not change the source-inventory counts or supply post-extraction coverage.

Before claiming preservation after extraction:

1. Bind the exact baseline and actually installed candidate ROMs, corresponding source/build/link identities, unchanged test executables/media and independent private state. Complete the broad API, targeted storage/save/reset and four supported build-profile checks on each relevant image; preserve TODO/exclusion/failure outcomes.
2. Extend the export-to-test/contract map where gaps matter, then validate compiler-bound call reachability and native execution records. Cover error/OOM, inline/pending completion, races, IRQL, reset/rundown and hardware paths separately. This map supplies no line/branch coverage percentage or physical Xbox qualification.
3. Complete the predeclared A/A calibration and paired untraced A/B performance experiment on each host. Retain per-case latency/throughput/tails and memory/ROM evidence; diagnostic allocation/copy/worker/command/IRQ and physical durability evidence remain separately qualified gates. Missing counters or flush evidence stay unknown.
4. Report every regression or inconclusive primary case. Source coverage, historical timings, successful gameplay and performance gates are distinct evidence; none substitutes for the others or for the separate provenance/license review.

The [qualification plan](TEST-PLAN.md), [P1 harness](PERFORMANCE-HARNESS.md) and executable checklist continue to own those acceptance gates. This map adds a reproducible inventory and makes its gaps inspectable; it does not close the combined acceptance gate.
