Public thread identity and lifetime prototype — qualification record
===================================================================

Scope and isolation
-------------------
This is an isolated prototype based on the exact async2 candidate. It does not
modify the current candidate or parent product. Public nxdk APIs and published
structures are the reference surface; Complex is executed only as an oracle.
No proprietary code or disassembly is inspected.

The demonstrated defect is that ObReferenceObjectByHandle returns a native
ETHREAD while KeGetCurrentThread returns a truncated public shadow. Public
GetExitCodeThread reads HasTerminated at 0x77 and ExitStatus at 0x120; the old
0x80-byte shadow cannot contain the latter. The handle and current-thread
pointers are also inconsistent. A larger allocation alone would not fix the
pointer-taking APIs, reference counting, waits, notifications or APC paths.

The prototype guarantees one registered public identity, a 0x140-byte backing
allocation, ID before creation notification/start, terminal status before the
native thread dispatcher signal, and identity lifetime until final object
reference deletion. It maps pointer consumers back to the canonical native
object before native object headers, scheduling, APC or wait operations.

This is NOT a complete live Xbox KTHREAD reimplementation. Public process/APC/
mutant/list links are not maintained as a live mirror; State/Priority/Quantum
can be stale after native scheduling, tick, delay or boosts. Setters publish
bounded control snapshots. Mutable creation metadata is not yet guaranteed.
The v4 wait adapter guarantees qualified post-return caller blocks and moves
its explicit user APC dispatch after their repair. Unrelated kernel APCs or
observers inspecting caller blocks while linked can still see native fields.

Pointer ownership and lookup
----------------------------
The public shadow is embedded at native KTHREAD+0x1b4. A 32-bucket exact-address
registry uses an 8-byte native link per thread and 256 static bytes on i386.
Registration follows complete initial publication; successful KeInit registers
once. Failed pre-init deletion sees zero links. Final PspDeleteThread removes
membership before native stack/CID storage is freed. Exit, handle closure and
notification do not remove membership or consume extra references.

Lookup never infers ownership from Header.Type, magic bytes, or a speculative
read of caller memory. A monotonic low-five-bit mask is a negative filter;
a present bit proves nothing. Native pool bodies and boot ETHREAD are aligned
to at least eight bytes, and the view offset is 4 modulo 8, so this exact
allocation scheme can accumulate at most four of 32 residue bits. Even if a
future allocator increased the mask density, it would only increase exact
lookup misses, not produce false ownership or false negatives. The bits are
not cleared on removal.

v4 caches one volatile exact public address from a successful registry match.
The cache is cleared under interrupt exclusion before registry removal. An
atomic pointer equality hit derives the native address from that same input;
there is no separately loaded native pointer that could tear with replacement.
A valid caller already holds an object reference or current-thread lifetime.
Use after final dereference is outside the object-pointer API contract.

Generic native event/file objects normally fail the residue filter inline.
Known referenced outbound objects may safely inspect their native object type
and return the thread shadow directly, without a generic registry search.
Current-thread equality is also a known-lifetime fast path. Cache misses scan
one bucket under brief UP interrupt exclusion. Synthetic 1-KiB aligned bodies
produce maximum bucket lengths 1/1/1/2/4/8/16 for 8/16/32/64/128/256/512 threads.

Memory and stack
----------------
Exact target compiler: KTHREAD 576 -> 776 bytes; ETHREAD 736 -> 936 bytes.
Including the 24-byte object header and 8-byte pool header, both remain in the
existing 1024-byte bucket. There is no per-thread external view allocation.
The registry/filter/cache add 264 static bytes; static boot thread grows 200
bytes. Actual page effects are checked natively, not inferred from body sizes.

Caller multiwait blocks require Count*24 backup bytes and Count*4 translated
object bytes: max 1792 bytes for 64 objects, plus ordinary function frames.
One/two-object waits allocate proportionally; NULL blocks need no backup.
Minimum native stack remains separately qualified by the actual thread-stack
suite. A native 64-object user APC/reentrant oracle is part of v4 qualification.

plus 320 create/destroy workers. After 64 warmup iterations, 256 steady workers

32 resident 16-KiB stacks cost 128 stack plus 8 pool pages; retired pool remains

v3 ABBA removed v2's generic object reference regression; event/file costs

translation cost is roughly 20 ns per pointer pair and 40-60 ns per other-thread
handle pair. Generic event/file paths have small residual effects/run spread;
no zero-overhead claim. cost-summary-v4.json preserves all medians.

Integration dependency
----------------------
Critical-section public owner identity is a separately qualified change,
PR230 / commit 86c2048d. This prototype's async2 base predates it. Combined
packaging must apply that independent owner patch first; this prototype does
not duplicate or overwrite its fix. Full live dispatcher owner/list identity
is outside this narrower thread identity/exit-status patch.
